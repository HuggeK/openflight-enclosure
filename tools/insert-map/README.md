# Insert map

A 3D viewer that shows every heat-set insert and screw hole in the enclosure STLs: where it is, its diameter and depth, and which side the insert or screw goes in from.

- Viewer: [`docs/viewer/index.html`](../../docs/viewer/index.html), published to GitHub Pages by [`.github/workflows/insert-map.yml`](../../.github/workflows/insert-map.yml).
- Data: [`docs/viewer/data/holes.json`](../../docs/viewer/data/holes.json), generated by [`analyze.py`](analyze.py).

## How the holes are found

`analyze.py` slices each STL every 0.2 mm along X, Y and Z and collects the small round holes in each slice. It then joins the slices that belong to the same hole and fits a straight axis through them, so tilted holes such as the 10° radar mounts come out right. For each hole it records:

| Field | Meaning |
| --- | --- |
| `d` | Diameter in mm, measured square to the hole axis |
| `depth` | Length of the hole in mm |
| `blind` | `true` if one end is closed |
| `entry` | Open end the insert or screw goes in from (for through holes, the end facing the back of the enclosure) |
| `dir` | Unit vector pointing into the hole |
| `tilt` | Degrees off the nearest X, Y or Z axis |
| `kind` / `label` | Size class guessed from the diameter (see `CLASSES`) |
| `role` | What the hole is for, from the position rules in `RULES` |

The diameter classes match the current models: M3 insert pockets are drawn at Ø4.4, M2.5 at Ø3.3–3.4, M2 at Ø2.8–3.0. A short hole that is open at both ends is reported as a clearance hole.

## Run it locally

```sh
pip install -r tools/insert-map/requirements.txt
python tools/insert-map/analyze.py      # about 4 minutes; rewrites docs/viewer/data/holes.json
python -m http.server                   # from the repo root
# open http://localhost:8000/docs/viewer/
```

Commit the updated `holes.json` together with STL changes, so the diff shows which holes moved or changed size. CI regenerates it as well and notes in the job summary if the committed file is stale.

## Linking to a build

The viewer keeps the chosen parts in the URL, for example:

```
viewer/?shell=Shell-x1202&radar=Front-Radar-No-Fill@experimental&screen=Screen-RPI-Display-2
```

Add `@experimental` or `@eol` to pick a part from that folder; without it the `v1` part is used.
